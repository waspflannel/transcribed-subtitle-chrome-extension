# Frontend

## Current State

- Known Lyrics follows Watch in the side-panel tab bar. Its labeled title/lyrics form saves browser-local entries with preview, Copy and Delete controls. See `product-specs/known-lyrics.md`.

- Website and extension interface locales are English, Spanish, Brazilian Portuguese, French, German, Japanese, Korean, Indonesian and Simplified Chinese. Native labels live in `packages/localization/locales.json`; separate `website` and `extension` JSON catalogs keep marketing copy out of extension bundles. Public website language comes from its URL: English uses existing unprefixed paths; other locales use `/es`, `/pt-br`, `/fr`, `/de`, `/ja`, `/ko`, `/id`, and `/zh-hans`. Public URLs ignore browser and cookie language, redirect old `?lang=` links, and expose self-canonicals and reciprocal alternate links from configured `APP_URL`. The public switcher keeps the page and uses direct language URLs. Auth/account pages retain query/cookie/browser selection and their existing paths. An encrypted one-year cookie carries website language into account screens. The extension's visible interface-language select saves `interfaceLocale` through existing settings broadcasts, with a Browser language option. Changing interface language preserves source/target languages, generated content, titles and drafts. Static marked copy updates only when locale changes; dynamic labels translate during render. Locale tests enforce catalog coverage and placeholders. Guide screenshot images remain English examples; captions and instructions are translated. New interface copy must update all nine catalogs and the native extension manifest messages where relevant.

- The transcript view has a saved-generation dropdown labeled source → target (Transcriber/Transcriber Spark). Options keep distinct job IDs even for the same language pair. Selection loads an existing track, updates the video overlay, and remembers it for that video without changing next-generation settings. The dropdown includes Delete selected generation, even with only one generation. Confirmed deletion removes its backend job and local remembered track, switches to an available saved generation, or returns to generation setup when none remain. Switching and deletion wait for any active generation or lyrics mutation to finish. Refresh retrieves all currently readable, unexpired completed generations for the video; global History remains capped at 25.

- Generate again and Lyric correction are direct buttons above transcript search. They open the existing generation and full-lyrics replacement screens.
- Each YouTube page load and settled SPA navigation validates the selected cached generation against the backend before restoring lyrics. Missing or deleted generations are forgotten and another saved generation is recovered when available. Dashboard deletion therefore takes effect on the next page entry or refresh; an already-open tab can retain its lyrics. No periodic deletion polling is added. Validation failures show a retry message and keep the cache for the next page refresh. Validation is the default for page-entry requests, including requests from older content scripts. Refresh saved generations also reconciles the displayed track with the returned list, updates both transcript and overlay, and returns to setup when no generations remain.


- The browser-extension frontend is a WXT **side panel** under `app/extension/entrypoints/sidepanel` (Chrome `side_panel` / Firefox `sidebar_action`), opened from the toolbar action via `openPanelOnActionClick`. It replaced the former toolbar popup, which is removed. The panel docks beside the page and reflows it (never overlaying YouTube) and can be collapsed.
- Panel markup is static in `index.html`: a labeled top tab bar — Watch · Known Lyrics · Study · History · Account — over a persistent "now playing" header and scrollable view sections. **Watch is state-driven**: inside one tab it swaps between an unsupported-page notice, an inline sign-in prompt, the generation setup (compact language-pair card with an expandable picker, layer chips, generate button), a current-activity progress display, and the ready transcript (direct Generate again and Lyric correction buttons, search, and cue list). `main.ts` bootstraps typed DOM handles (`dom.ts`), event wiring, and background messages; feature renderers live under `entrypoints/sidepanel/render/`, view labels in `view-model.ts`, tab/view switching reuses `tabs.ts` (`setupTabs`/`showTab` over `data-tab`/`data-panel`), and timing persistence lives in `timing-control.ts`. The panel opens on Watch because its internal state replaces the old tab-teleporting defaults.
- Panel CSS is the marketing site's "ink & marker" system on its night palette (`entrypoints/sidepanel/style.css`, tokens mirroring `app/backend/public/css/site/tokens.css`): solid `#000` ground, bone-paper text, single `#d83b3b` crimson accent, hard borders with an offset-shadow primary button, `//`-prefixed mono micro-labels, and bundled Bricolage Grotesque / Schibsted Grotesk / Spline Sans Mono (`@fontsource/*`). The on-video overlay keeps its own Geist + IBM Plex Mono files under `public/fonts` via `web_accessible_resources`.
- The in-page YouTube overlay shell is exported from `app/extension/utils/overlay.ts` into an isolated Shadow DOM host. Overlay render functions, shared types, and Shadow DOM styles live under `app/extension/utils/overlay/`.
- Study → Caption display includes **Attach subtitles to video**, enabled by default. Uncheck it to expose a Move subtitles handle for pointer dragging or arrow-key movement (Shift takes larger steps). The detached rail stays in the page viewport across cue changes and scrolling; resize/fullscreen changes keep its handle reachable. Check attachment again to discard its temporary coordinates and snap to the selected Bottom, Top or Compact preset. The checkbox is saved locally; coordinates last only while the overlay is mounted.
- The content script binds ready tracks to the page's primary `<video>` element, resolves browser `TextTrack` cue changes back to the matching API cue, and avoids replacing overlay HTML when rendered content has not changed. Subtitle delivery is pull-first: on YouTube SPA navigation the script clears state and re-pulls from the background after a short debounce, retries binding briefly when the `<video>` element is not mounted yet, and skips rebinding when the same finalized track is re-delivered (rebinding would reset the text track and drop the active cue). On the pull path the background recovers completed and in-flight jobs for the page's video from backend job history (`content.getState` → `recoverSubtitleStateFromBackend`), so previously generated tracks appear without a refresh or a regenerate even when they have fallen out of the small remembered-track cache; stale failed jobs are not surfaced on load.
- The overlay renders a Shadow DOM language rail with source-token cards, cue timing, optional selected-target cue translation, optional romanization/gloss metadata, hover preview, click/tap pinned token detail, scoped blur/reveal study controls, cue replay, cue copy, keyboard shortcut status, and caption size/density/contrast preferences. Token-card reveal includes the token text plus that token's romanization when present; the full cue romanization line and translation line reveal independently on their own hover/focus. The rail, token cards, and popovers share the black + crimson brand palette (crimson cue timing, token hover/pin) with a high-contrast red/white theme variant.
- The transcript lives in the side panel as the Watch tab's **ready state** (`utils/panel/transcript.ts` renderer + `entrypoints/sidepanel/transcript-view.ts` controller): a searchable cue list with jump/replay (which seek the video), copy, and a save placeholder. When romanization is enabled and a cue's tokens carry per-word readings, each word renders with its romaji riding above it (the site's player-mock motif); otherwise the row falls back to the plain source line with a whole-line romanization. Each transcript line has an Edit action exposing word selection for that line and a correction form beneath it. Whole-track actions live above transcript search and open mutually exclusive Watch screens with Back to transcript. Full replacements validate obvious junk and require all pasted parts to be allocated to known ordered timing slots. Partial merging is unavailable. Replacement runs behind a compact status strip; View progress opens stages and cancellation. The content script relays the playing cue to the panel through the background hub (`content.activeCueChanged` → `background.activeCueChanged`), so the panel highlights the active cue without scrolling or moving editor focus; the panel's jump/replay round-trip back through the background (`panel.seekToCue` → `background.seekToCue`) to seek the bound video. The on-video overlay no longer renders a transcript — it shows only the caption rail and word card.
- The content script owns YouTube-page keyboard shortcuts for replay, previous/next cue navigation, translation visibility, source-word blur, hover pause, focusing the side-panel transcript, cue copy, and the Phase 02 save-current-cue placeholder. Shortcut dispatch ignores editable targets.
- The content script temporarily pauses the active YouTube video when a source token is hovered or focused if the local Study setting is enabled. It resumes playback when the token loses hover/focus, or as a fallback when the pointer leaves the rail, only if the extension caused the pause. Blank rail hover and manual video pause do not reveal blurred text.
- The overlay calls the background script for on-click token enrichment when a token only has transcript/romanization data, then re-renders from the patched backend track.
- Panel content map: **Watch** owns the whole generation loop — language pair + layer chips (Translation / Romanization; the single source of truth for `showTranslation`/`showRomanization`), the generate button with a plan-minutes note and privacy copy, backend-synced progress rendered as the current activity and percentage, an error banner, and the ready transcript. The now-playing header shows the active tab's real video title (`pageTitle` on `PanelState`, stripped of YouTube chrome) over duration and language route. **Study** keeps caption display (show overlay, position, caption size, density, contrast, gloss, timing delay with reset), active-recall blurs (source/romanization/translation, hover-pause), keyboard shortcuts (enable toggle + help list), and a This-device zone (language defaults summary, clear-local-state). **History** (formerly Jobs) lists public-safe jobs grouped by Videos/Shorts as video-first cards: linked title, plain-word status pill (Queued / Generating · % / Ready / Failed), compact meta line, current-stage or error message, and navigation-only Open video links. **Account** keeps sign-in/out, an account/billing link, plan facts, generation preferences, billing denial copy, and the usage meter. The panel stays responsive down to 320px.
- The panel exposes a manual subtitle timing delay from -10s to +10s. Dragging the range updates local display immediately and persists the setting on a short debounce; number/reset controls commit immediately. The content script applies the setting locally by rebinding the generated WebVTT track with shifted cue timings.
- The Laravel web app serves the website and account surface from server-rendered Blade pages in the red/black "ink & marker" design. The landing page links its hero, guide introduction, and lyrics feature to `/how-to-use`; the former interactive preview and its CSS/JS are removed. The public guide starts with Chrome Web Store and unpacked ZIP installation, then documents the current extension controls with a sticky desktop contents sidebar and a native collapsible mobile contents list. Anchors work without JavaScript; optional scroll tracking marks the current section. The guide alone loads `guide.css`, and accepts figures with images or captioned videos beside the relevant instructions. Public beta marketing copy is removed while pricing, sign-in, subscriptions, and account controls remain. `/extension` and `/desktop` redirect to `/how-to-use#how-to-install`; `/how-it-works` redirects to `/how-to-use`; `/languages` and `/faq` keep their home anchors. Privacy, terms, support, `robots.txt`, and `sitemap.xml` retain canonical/social metadata, with the guide included in the sitemap. Support focuses on bugs/contact and links to guide installation. Authenticated pages show plan, usage, Stripe-hosted billing, extension connections, recent jobs, and owner-scoped public-safe job details. Job details use a centered readable width and fixed inner gutters so viewport-sized padding cannot collapse the content. Website CSS uses ordered links under `app/backend/public/css/site/`; repeated Blade UI lives under `app/backend/resources/views/components/`.
- History actions are navigation-only Open video links, not selected-job retries. Failed cards explain that options must be reviewed in Watch and are not restored. Account exposes a dashboard/billing link on the configured backend origin and labels generation settings as preferences rather than entitlement promises. All new password-related UX additions, including hints/minlength and recovery/verification links, were withdrawn at user request; password rules remain unchanged; current registration does not enforce email verification.

## Expectations

- How To Use includes seven double-density screenshots captured with agent-browser: Chrome manual installation and the actual extension generation, transcript, lyrics replacement, word correction, caption display/timing, and active recall views. Extension captures use identified sample content through the local review fixture. The shared `guide-screenshot` Blade component overlays SVG highlights and numbered circles with matching text captions, native full-size image links, explicit dimensions, and lazy loading. Figures place captions beside images on wide screens and stack on narrow screens. Capture provenance and QA evidence live in `docs/review-evidence/2026-09-16-guide-screenshots/README.md`.

- The generation source picker is labeled Video language. It resets to Auto detect when the panel opens or reloads, or when the selected video or tab changes. A manual selection stays in place during ordinary state refreshes for the same video. The reset is saved before generation becomes available; the translation language and existing jobs keep their settings.

- Website motion lives in the existing `motion.css` with easing/duration tokens in `tokens.css`. Native smooth anchors keep fixed-header offsets; native page transitions, scroll-progress styling, and intrinsic-size disclosure transitions progressively enhance supporting browsers. Reveal blocks use an intersection threshold of zero so tall content remains reachable on short viewports, and keyboard-focused blocks show immediately. Reduced motion removes both movement and delays and exposes every reveal block without requiring a reload.
- Extension screen entrances are CSS animations on persistent tab/Watch containers. Switch thumbs use transforms; cue rows and pinned word cards remain stationary. The panel and isolated overlay each suppress animations and transitions for reduced motion. Validate progress updates, cue changes, and draft focus when changing these styles.

- A local track-cache miss queries the existing video-filtered completed-history API, even when global History contains an obsolete completed version. Active generation recovery still uses global History and persisted operations. An active monitor owns polling; local-only panel refreshes do not reload completed tracks or duplicate its status requests. Monitor-free persisted operations can recover after a service-worker restart.
- Completed lyrics results publish once per accepted attempt. Repeated terminal snapshots cannot overwrite newer local word-card metadata. Scroll/resize work is coalesced into one animation frame and positions the overlay without rebuilding its content. Transcript search caches searchable text, invalidates it on cue/word-card/Quick fix changes, and coalesces input rendering per frame. Annotation-only partial revisions keep the existing native timing track.
- Side-panel fonts use WOFF2-only declarations in `entrypoints/sidepanel/fonts.css`, preserving used weights and language subsets. The overlay loads only its used Geist and IBM Plex Mono faces. Website CSS uses eight ordered, individually timestamp-versioned stylesheet links from the site layout.

- Watch generation includes an AI model select with Transcriber (default) and Transcriber Spark. The selection is saved in extension settings and captured when Generate is pressed; changing it leaves running jobs and saved tracks on their original model. Jobs display their saved provider, and Account displays the next generation selection. Language pickers show label and code only — no Excellent/Good/Moderate badges.
- The same selector offers Auto. Auto chooses once from transcript content; the account and confirmation show Auto, pending job history shows Auto, and resolved history/saved tracks show the actual selected model. Existing defaults and manual choices remain unchanged.
- Generation offers optional names/vocabulary for that video only: up to 20 terms, each at most five words and 49 characters. Inputs clear after submission or video/account changes and are not saved as global preferences. A completed cue with `translatedText: ""` means requested translation was unavailable; the transcript labels this and the overlay hides the empty line. Disabled/same-language translation still retains source text.

- The internal `tokenizing` generation stage is displayed as **Analyzing subtitles** in the extension and web dashboard. Tokenization, translation, and requested romanization share one analysis response, progress band, and timeline step; the timeline must not show translation and romanization as later sequential steps.

- Running generation status includes available preview cues. Poll running jobs once per second and queued jobs or failed requests every five seconds. Each loop waits at least one second per active tab operation to share the status rate limit (about 60 requests per minute across active tabs, plus initial reads). Only changed preview revisions are stored again; completion and cancellation stop polling.
- The Watch progress screen shows the backend percentage and current real pipeline activity instead of a fixed stage checklist. Transcription and analysis batch completions advance the bar within their progress bands. Before the first preview cue arrives, the on-video subtitle rail stays on a stable **Generating** placeholder; it switches to partial subtitle cues only when a non-empty batch is available.

- Dashboard connection listings filter both per-token and configured Sanctum expiration before taking three recent extension tokens. This is a token-status snapshot, not browser-presence detection; viewing it does not revoke tokens.

- Dashboard and job-detail pages expose native GET "Refresh status" links and timestamped snapshot labels; they do not poll. Source videos are identified by stored IDs and canonical YouTube links. Dashboard Clear all shows the full owned-job count, including jobs outside the recent list/processing versions, and explains track and usage consequences before confirmation.

- Keep the WXT extension bootable from the documented `app/extension` package commands.
- Add browser-driven validation for important user journeys.
- Capture screenshots or videos for UI fixes and visual regressions.
- Keep DOM state, routes, errors, and network failures legible to agents.
- Keep privacy and failure copy visible in the panel or overlay when video-derived audio/text leaves the browser or generation fails.
- Keep playback sync listeners direct and inspectable; add YouTube DOM fallbacks only after a concrete failure.
- Prefer reusable components once a pattern repeats.

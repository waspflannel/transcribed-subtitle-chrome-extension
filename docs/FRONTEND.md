# Frontend

## Current State

- The browser-extension frontend is a WXT **side panel** under `app/extension/entrypoints/sidepanel` (Chrome `side_panel` / Firefox `sidebar_action`), opened from the toolbar action via `openPanelOnActionClick`. It replaced the former toolbar popup, which is removed. The panel docks beside the page and reflows it (never overlaying YouTube) and can be collapsed.
- Panel markup is static in `index.html` (a left icon rail — Generate · Study · Transcript · Jobs · Account — and a persistent "now playing" header over scrollable view sections). `main.ts` bootstraps typed DOM handles (`dom.ts`), event wiring, and background messages; feature renderers live under `entrypoints/sidepanel/render/`, view labels in `view-model.ts`, rail/view switching reuses `tabs.ts` (`setupTabs`/`showTab` over `data-tab`/`data-panel`), timing persistence in `timing-control.ts`, and `utils/panel/view-state.ts` (`selectDefaultView`) picks the state-aware default view (Account when signed out, Study when a track is ready, else Generate).
- Panel CSS is the sharp brand system in `entrypoints/sidepanel/style.css`: square corners (zero radius), hairline rules and IBM Plex Mono micro-labels instead of rounded cards, native `<select>`/checkbox/range controls restyled sharp, and bundled Geist (`@fontsource/geist-sans`) + IBM Plex Mono fonts (also loaded into the overlay Shadow DOM via `web_accessible_resources`).
- The in-page YouTube overlay shell is exported from `app/extension/utils/overlay.ts` into an isolated Shadow DOM host. Overlay render functions, shared types, and Shadow DOM styles live under `app/extension/utils/overlay/`.
- The content script binds ready tracks to the page's primary `<video>` element, resolves browser `TextTrack` cue changes back to the matching API cue, and avoids replacing overlay HTML when rendered content has not changed.
- The overlay renders a Shadow DOM language rail with source-token cards, cue timing, optional selected-target cue translation, optional romanization/gloss metadata, hover preview, click/tap pinned token detail, scoped blur/reveal study controls, cue replay, cue copy, keyboard shortcut status, and caption size/density/contrast preferences. Token-card reveal includes the token text plus that token's romanization when present; the full cue romanization line and translation line reveal independently on their own hover/focus. The rail, token cards, and popovers share the black + crimson brand palette (crimson cue timing, token hover/pin) with a high-contrast red/white theme variant.
- The transcript now lives in the side panel as its own **Transcript** view (`utils/panel/transcript.ts` renderer + `entrypoints/sidepanel/transcript-view.ts` controller): a searchable cue list with jump/replay (which seek the video), copy, and a save placeholder. The content script relays the playing cue to the panel through the background hub (`content.activeCueChanged` → `background.activeCueChanged`), so the panel highlights and auto-scrolls to the active cue live; the panel's jump/replay round-trip back through the background (`popup.seekToCue` → `background.seekToCue`) to seek the bound video. The on-video overlay no longer renders a transcript — it shows only the caption rail + word card.
- The content script owns YouTube-page keyboard shortcuts for replay, previous/next cue navigation, translation visibility, source-word blur, hover pause, focusing the side-panel transcript, cue copy, and the Phase 02 save-current-cue placeholder. Shortcut dispatch ignores editable targets.
- The content script temporarily pauses the active YouTube video when a source token is hovered or focused if the local Study setting is enabled. It resumes playback when the token loses hover/focus, or as a fallback when the pointer leaves the rail, only if the extension caused the pause. Blank rail hover and manual video pause do not reveal blurred text.
- The overlay calls the background script for on-click token enrichment when a token only has transcript/romanization data, then re-renders from the patched backend track.
- The side panel is styled in the sharp black + crimson brand (matching the website: `#0a0a0a` surfaces, `#d83b3b` crimson accent, bundled Geist + IBM Plex Mono type, square corners, hairline rules). A persistent left icon rail switches between Generate, Study, Jobs, and Account views beneath a sticky "now playing" header; the panel opens on a state-aware default view (Account when signed out, Study when a track is ready, else Generate). Generate holds the now-playing status, searchable Subtitle/Translation language pickers, Translate subtitles/Romanization/Full word cards controls, backend-synced progress including the visible `Optimizing audio` stage, and stable public error copy. Study consolidates caption display (show overlay, position, caption size, density, contrast, gloss, timing delay) with the study controls (blur source/romanization/translation, hover-pause, keyboard shortcuts) and keyboard shortcut help. Account consolidates backend account/usage summaries, feature availability, billing denial copy, and a Local data zone with the clear-local-state control. Jobs lists public-safe job timelines grouped by Videos/Shorts, each row linking to its YouTube video. The panel stays responsive down to 320px (grids collapse to a single column under 360px).
- The panel exposes a manual subtitle timing delay from -10s to +10s. Dragging the range updates local display immediately and persists the setting on a short debounce; number/reset controls commit immediately. The content script applies the setting locally by rebinding the generated WebVTT track with shifted cue timings.
- The Laravel web app now serves the beta SaaS website and account surface from server-rendered Blade pages. Public pages cover home, `/desktop`, pricing, language coverage, how it works, FAQ, privacy, terms, support, `robots.txt`, and `sitemap.xml` with canonical and social metadata. Authenticated pages show plan, usage, Stripe-hosted billing actions, extension connection state, recent jobs, and owner-scoped public-safe job detail pages. Website CSS is loaded from `app/backend/public/css/site.css`, which imports split files under `app/backend/public/css/site/`; repeated Blade UI lives under `app/backend/resources/views/components/`. The homepage and `/desktop` use a scoped Hermes Desktop black-theme landing layout from the user-supplied design document; the remaining website/account visual direction stays Stitch-led dark academia.

## Expectations

- Keep the WXT extension bootable from the documented `app/extension` package commands.
- Add browser-driven validation for important user journeys.
- Capture screenshots or videos for UI fixes and visual regressions.
- Keep DOM state, routes, errors, and network failures legible to agents.
- Keep privacy and failure copy visible in the panel or overlay when video-derived audio/text leaves the browser or generation fails.
- Keep playback sync listeners direct and inspectable; add YouTube DOM fallbacks only after a concrete failure.
- Prefer reusable components once a pattern repeats.

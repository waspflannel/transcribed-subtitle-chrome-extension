# Frontend

## Current State

- The transcript view has a saved-generation dropdown labeled source → target (Luna/Cerebras). Options keep distinct job IDs even for the same language pair. Selection loads an existing track, updates the video overlay, and remembers it for that video without changing next-generation settings. Refresh retrieves all currently readable, unexpired completed generations for the video; global History remains capped at 25. Switching waits for any active generation or lyrics mutation to finish.


- The browser-extension frontend is a WXT **side panel** under `app/extension/entrypoints/sidepanel` (Chrome `side_panel` / Firefox `sidebar_action`), opened from the toolbar action via `openPanelOnActionClick`. It replaced the former toolbar popup, which is removed. The panel docks beside the page and reflows it (never overlaying YouTube) and can be collapsed.
- Panel markup is static in `index.html`: a labeled top tab bar — Watch · Study · History · Account — over a persistent "now playing" header and scrollable view sections. **Watch is state-driven**: inside one tab it swaps between an unsupported-page notice, an inline sign-in prompt, the generation setup (compact language-pair card with an expandable picker, layer chips, generate button), a named-stage progress checklist, and the ready transcript (search + cue list + an actions menu opening dedicated Replace full lyrics and Generate again screens). `main.ts` bootstraps typed DOM handles (`dom.ts`), event wiring, and background messages; feature renderers live under `entrypoints/sidepanel/render/`, view labels in `view-model.ts`, tab/view switching reuses `tabs.ts` (`setupTabs`/`showTab` over `data-tab`/`data-panel`), and timing persistence lives in `timing-control.ts`. The panel opens on Watch because its internal state replaces the old tab-teleporting defaults.
- Panel CSS is the marketing site's "ink & marker" system on its night palette (`entrypoints/sidepanel/style.css`, tokens mirroring `app/backend/public/css/site/tokens.css`): `#0e0e0e` ground with faint ruled-notebook lines, bone-paper text, single `#d83b3b` crimson accent, hard borders with an offset-shadow primary button, `//`-prefixed mono micro-labels, and bundled Bricolage Grotesque / Schibsted Grotesk / Spline Sans Mono (`@fontsource/*`). The on-video overlay keeps its own Geist + IBM Plex Mono files under `public/fonts` via `web_accessible_resources`.
- The in-page YouTube overlay shell is exported from `app/extension/utils/overlay.ts` into an isolated Shadow DOM host. Overlay render functions, shared types, and Shadow DOM styles live under `app/extension/utils/overlay/`.
- The content script binds ready tracks to the page's primary `<video>` element, resolves browser `TextTrack` cue changes back to the matching API cue, and avoids replacing overlay HTML when rendered content has not changed. Subtitle delivery is pull-first: on YouTube SPA navigation the script clears state and re-pulls from the background after a short debounce, retries binding briefly when the `<video>` element is not mounted yet, and skips rebinding when the same finalized track is re-delivered (rebinding would reset the text track and drop the active cue). On the pull path the background recovers completed and in-flight jobs for the page's video from backend job history (`content.getState` → `recoverSubtitleStateFromBackend`), so previously generated tracks appear without a refresh or a regenerate even when they have fallen out of the small remembered-track cache; stale failed jobs are not surfaced on load.
- The overlay renders a Shadow DOM language rail with source-token cards, cue timing, optional selected-target cue translation, optional romanization/gloss metadata, hover preview, click/tap pinned token detail, scoped blur/reveal study controls, cue replay, cue copy, keyboard shortcut status, and caption size/density/contrast preferences. Token-card reveal includes the token text plus that token's romanization when present; the full cue romanization line and translation line reveal independently on their own hover/focus. The rail, token cards, and popovers share the black + crimson brand palette (crimson cue timing, token hover/pin) with a high-contrast red/white theme variant.
- The transcript lives in the side panel as the Watch tab's **ready state** (`utils/panel/transcript.ts` renderer + `entrypoints/sidepanel/transcript-view.ts` controller): a searchable cue list with jump/replay (which seek the video), copy, and a save placeholder. When romanization is enabled and a cue's tokens carry per-word readings, each word renders with its romaji riding above it (the site's player-mock motif); otherwise the row falls back to the plain source line with a whole-line romanization. Each transcript line has an Edit action exposing word selection for that line and a correction form beneath it. Whole-track actions live in the transcript menu and open mutually exclusive Watch screens with Back to transcript. Suspected incomplete replacements offer an explicit inline warning before resubmitting the same draft with permission for AI to merge it with existing lyrics. Editing the draft or changing the video/track invalidates that permission. Replacement runs behind a compact status strip; View progress opens stages and cancellation. The content script relays the playing cue to the panel through the background hub (`content.activeCueChanged` → `background.activeCueChanged`), so the panel highlights the active cue without scrolling or moving editor focus; the panel's jump/replay round-trip back through the background (`panel.seekToCue` → `background.seekToCue`) to seek the bound video. The on-video overlay no longer renders a transcript — it shows only the caption rail and word card.
- The content script owns YouTube-page keyboard shortcuts for replay, previous/next cue navigation, translation visibility, source-word blur, hover pause, focusing the side-panel transcript, cue copy, and the Phase 02 save-current-cue placeholder. Shortcut dispatch ignores editable targets.
- The content script temporarily pauses the active YouTube video when a source token is hovered or focused if the local Study setting is enabled. It resumes playback when the token loses hover/focus, or as a fallback when the pointer leaves the rail, only if the extension caused the pause. Blank rail hover and manual video pause do not reveal blurred text.
- The overlay calls the background script for on-click token enrichment when a token only has transcript/romanization data, then re-renders from the patched backend track.
- Panel content map: **Watch** owns the whole generation loop — language pair + layer chips (Translation / Romanization; the single source of truth for `showTranslation`/`showRomanization`), the generate button with a plan-minutes note and privacy copy, backend-synced progress rendered as a named-stage checklist (`stageTimeline`), an error banner, and the ready transcript. The now-playing header shows the active tab's real video title (`pageTitle` on `PanelState`, stripped of YouTube chrome) over duration and language route. **Study** keeps caption display (show overlay, position, caption size, density, contrast, gloss, timing delay with reset), active-recall blurs (source/romanization/translation, hover-pause), keyboard shortcuts (enable toggle + help list), and a This-device zone (language defaults summary, clear-local-state). **History** (formerly Jobs) lists public-safe jobs grouped by Videos/Shorts as video-first cards: linked title, plain-word status pill (Queued / Generating · % / Ready / Failed), compact meta line, current-stage or error message, and navigation-only Open video links. **Account** keeps sign-in/out, an account/billing link, plan facts, generation preferences, billing denial copy, and the usage meter. The panel stays responsive down to 320px.
- The panel exposes a manual subtitle timing delay from -10s to +10s. Dragging the range updates local display immediately and persists the setting on a short debounce; number/reset controls commit immediately. The content script applies the setting locally by rebinding the generated WebVTT track with shifted cue timings.
- The Laravel web app serves the beta SaaS website and account surface from server-rendered Blade pages in the red/black "ink & marker" design. Public pages are a single landing page (night hero, CSS product mock, features, how-it-works, languages, pricing, and FAQ as anchored sections), a thin `/pricing` page, privacy, terms, support, `robots.txt`, and `sitemap.xml` with canonical and social metadata; retired pages (`/extension`, `/desktop`, `/languages`, `/how-it-works`, `/faq`) 301-redirect to home anchors. Authenticated pages show plan, usage, Stripe-hosted billing actions, extension connection state, recent jobs, and owner-scoped public-safe job detail pages, re-skinned to the same system. Website CSS is loaded from `app/backend/public/css/site.css`, which imports split files under `app/backend/public/css/site/` (tokens in `tokens.css`); repeated Blade UI lives under `app/backend/resources/views/components/`.
- History actions are navigation-only Open video links, not selected-job retries. Failed cards explain that options must be reviewed in Watch and are not restored. Account exposes a dashboard/billing link on the configured backend origin and labels generation settings as preferences rather than entitlement promises. All new password-related UX additions, including hints/minlength and recovery/verification links, were withdrawn at user request; pre-existing auth routes, verification enforcement, and password rules are unchanged.

## Expectations

- Watch generation includes an AI model select with Luna (default) and Cerebras. The selection is saved in extension settings and captured when Generate is pressed; changing it leaves running jobs and saved tracks on their original model. Jobs display their saved provider, and Account displays the next generation selection.
- Generation offers optional names/vocabulary for that video only: up to 20 terms, each at most five words and 49 characters. Inputs clear after submission or video/account changes and are not saved as global preferences. A completed cue with `translatedText: ""` means requested translation was unavailable; the transcript labels this and the overlay hides the empty line. Disabled/same-language translation still retains source text.

- The internal `tokenizing` generation stage is displayed as **Analyzing subtitles** in the extension and web dashboard. Tokenization, translation, and requested romanization share one analysis response, progress band, and timeline step; the timeline must not show translation and romanization as later sequential steps.

- Running generation status includes available preview cues. Poll running jobs once per second and queued jobs or failed requests every five seconds. Each loop waits at least one second per active tab operation to share the status rate limit (about 60 requests per minute across active tabs, plus initial reads). Only changed preview revisions are stored again; completion and cancellation stop polling.

- Dashboard connection listings filter both per-token and configured Sanctum expiration before taking three recent extension tokens. This is a token-status snapshot, not browser-presence detection; viewing it does not revoke tokens.

- Dashboard and job-detail pages expose native GET "Refresh status" links and timestamped snapshot labels; they do not poll. Source videos are identified by stored IDs and canonical YouTube links. Dashboard Clear all shows the full owned-job count, including jobs outside the recent list/processing versions, and explains track and usage consequences before confirmation.

- Keep the WXT extension bootable from the documented `app/extension` package commands.
- Add browser-driven validation for important user journeys.
- Capture screenshots or videos for UI fixes and visual regressions.
- Keep DOM state, routes, errors, and network failures legible to agents.
- Keep privacy and failure copy visible in the panel or overlay when video-derived audio/text leaves the browser or generation fails.
- Keep playback sync listeners direct and inspectable; add YouTube DOM fallbacks only after a concrete failure.
- Prefer reusable components once a pattern repeats.
